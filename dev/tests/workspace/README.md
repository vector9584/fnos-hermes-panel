# 会话工作区与专家协作：设计和验收记录

日期：2026-11-04。适用本机 Hermes 0.21.149 内核 / fnOS 控制面板。

## 产品边界

- **会话角色 = 专家设定快照**。选择专家只影响该会话下一次回复的职责、方法、风格；不会激活全局 Profile。当前环境的模型、SOUL、长期记忆、技能和工具仍共享。专家的技能清单只是优先参考建议，不会自动安装技能，也不是权限隔离。
- **SOUL / 独立 Agent 环境 = Profile**。现有内核仍是全局单激活。需要独立人格、记忆、技能目录、模型配置时进入专家页的「高级环境设置」。切换全局环境会影响网关及其他渠道；本次未实现按会话隔离的多 Profile 运行。
- **专家群聊 = 独立成员会话 + 房间上下文**。每位成员有自己的会话记录和专家设定，工具/技能/长期记忆仍来自同一环境。适合方案评审、观点对比、分工。现有主持人自动接力机制保留，未把角色提示词误称为独立部署的 Agent。
- **文件夹 = 组织层**。支持多级目录，与角色、模型、Profile 互不绑定。
- **名称和头像**。会话侧栏齿轮设置用户、默认助手的显示名称和头像。头像支持 PNG、JPEG、WebP 上传，服务端裁剪/校验后的内容寻址 URL 存在独立头像目录；选专家后用专家名称/头像，新回复保存身份快照；切角色不改旧专家回复署名。修改默认显示身份可更新默认助手和用户的显示。

## 用户入口

| 位置 | 行为 |
|---|---|
| 会话左上角色卡 | 搜索、选择该会话的专家，或恢复默认助手 |
| 左侧加号 | 新会话、新文件夹、名称与头像 |
| 文件夹旁加号 / 省略号 | 建子文件夹；改名、移动、删除；删除时内容移到上一级 |
| 会话旁铅笔 | 一次编辑名称和归类 |
| 左侧搜索 | 查面板 JSON、渠道 SQLite、群聊 JSON 的标题和消息正文；结果片段高亮，可翻页；点击定位原消息 |
| 专家页 | 常用收藏 / 全部内置；开始对话、加入群聊、收藏、查看并编辑设定 |
| 加入群聊 | 创建新房间或加入已有房间；全库搜索，不再截断为前 140 位 |
| 声音与朗读 | Windows IndexTTS 默认、系统回退、当前 Windows 音色、系统音色、情绪、播放速度、试听和语音交互开关 |

专家库实际合并显示 315 项（含内置精选、工作流角色、MBTI 等）。具体数量随库更新。

## 实现

新增 `app/server/panel-workspace.js`、`panel-search.py`，前端独立 `ui/js/panel-workspace-ui.js`、`ui/css/panel-workspace.css`。`index.html` 只接入口与必要挂钩。显示/目录/会话角色配置存于 `$DATA_DIR/panel-workspace.json`，原子写入、600 权限，独立于 config.yaml；所有新写接口要求 Monitor token。

Monitor 在 SSE / WS 起始时读取角色快照并注入 system，checkpoint/finalize 保存 sender、sender_avatar、sender_kind、expert_id。原来的中断工具保存修复保持有效。

群聊修复：创建/追加成员保存 system；旧房间根据专家库及覆盖层恢复缺失设定；@ 与接力都使用成员设定；GET 轮询不再重建活跃对象并清掉接力锁；修正 `/[object Object]/g` 错误字符类，避免英文字符被成批删除。

搜索：面板和房间按原始消息下标定位；渠道使用 SQLite 消息 id 并显示命中前后上下文。FTS trigram 加速三字以上关键词，短词用只读子串查询；7 秒预算，超时明确标记 partial。当前数据实测约 1 秒。搜索正文不涵盖附件内文或未落盘的流式片段；渠道搜索预览只读，输入框隐藏。

语音：固定 loopback 8902 语音工作台读取/选择现有音色；调用既有 `scripts/tts_windows.py` 合成，情绪开关显式传入进程。不使用会把 config.yaml TTS 块改成 Edge 的旧保存接口。Windows 失败后调用独立 Edge 合成，再失败才进入浏览器 speechSynthesis。默认整个回复完成后合成，180 秒上限、16000 字上限，超限明确回退；关闭播放不保证中止 Windows 端已经在执行的合成。

## 部署与回滚

统一部署完整依赖：

```bash
cd /vol1/@apphome/hermes-agent/data/workspace/fnos-hermes-agent-src
dev/deploy-workspace.sh               # 检查、逐个备份、原位写入、唯一合法重启
dev/deploy-workspace.sh --no-restart  # 仅 UI 改动；后端改动不能省略后续重启
```

部署保持运行文件属主 hermes-agent。升级覆盖后必须一起恢复新增模块，不能只铺 monitor.js 或 index.html。

本次部署前基线 `16ece2b`；初始运行文件备份：`$DATA_DIR/backups/workspace-20261104-214509/`，数据备份：`workspace-data-20261104-214448/`；整机快照：`backup/snapshots/hermes-20261104-205030.tar.gz`。源仓库有完整提交，不自动 push。

需要撤销时，先确认没有其他未提交变更，使用该功能提交的 `git revert` 回退被修改文件；旧版本不引用新模块，因此不必删除多余文件。用 `cat` 原位恢复 `ui/index.html`、`server/monitor.js`、`server/custom_routes.js`，再运行 `dev/hermes-dev.sh restart`。`panel-workspace.json` 可保留，原会话正文不需要回滚。不要用整仓 `git reset --hard` 丢弃其他人的工作。

测试在 `dev/tests/workspace/`。通过 as_agent / sudo -u hermes-agent 使用 node 和 venv Python。隔离测试可重复执行；`test-live-workspace.mjs` 会创建短暂的真实模型会话并在 finally 清理，群聊自动记忆需检查是否产生测试条目，不作为每次部署必跑的常规测试。
